# ADR-006: Procedural Art Generation Is a Named Pattern with a Shared Engine Helper

**Status:** Accepted
**Date:** August 2026

## Context

The studio has built procedural art generation in at least three places:

- Dissonance Depths uses a Python script to generate static SVG files from
  YAML data (`scripts/generate_dissonance_art.py`).
- SlimeWorld's `SlimeVisual.tsx` generates SVG polygons at runtime using a
  seeded PRNG and per-slime shape parameters.
- Shoal's `App.tsx` draws fish and sharks as raw Canvas primitives every
  frame.

The same low-level concerns appear in each place: deterministic seeded
randomness, color blending, shape primitives, and tier-based styling. The
earlier ADR-005 decision prevents creating a shared binary that games must
import into their runtime logic, but it does not prevent extracting genuinely
identical primitives into a helper module that each game's own generator or
renderer can call.

## Decision

Procedural art generation is a **named pattern** documented here. The studio
maintains a small, game-agnostic helper module at `ts/src/engine/artGen/`
containing the reusable primitives: seeded PRNG, gradient and border
helpers, a generic icon shape library, and polygon / silhouette generation.

Each game implements its own art generator or renderer in its own source
tree, providing a per-game `ArtGenConfig` object that maps its own entities
to the generic primitives. The helper module never contains game-specific
vocabulary (e.g., `ember`, `fish`, `slime`).

This is consistent with ADR-005: the pattern is shared and documented, but
the per-game implementations remain separate and self-contained.

## Consequences

- A new game can adopt the pattern without importing another game's literal
  generator.
- Existing games keep their current behavior. Rewiring Shoal or SlimeWorld
  to consume the helper module is explicit follow-up work, not part of this
  decision.
- Dissonance's Python SVG generator remains a legitimate, separate solution
  to a similar problem and is not required to migrate to the TypeScript
  module.
- The module is tested by proving it can reproduce the existing committed
  Dissonance card SVGs and that the extracted RNG matches the original
  SlimeWorld implementation.
