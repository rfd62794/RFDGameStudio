# ADR-011: Logic-Layer Modularization by Size, SoC, and SRP

**Status:** Accepted
**Date:** July 2026
**Supersedes:** ADR-001's "exactly three files... no exceptions" clause,
for the internal organization of the logic layer only.
**Related:** ADR-009 (shared Lua utility primitives — cross-game
sharing via `engine/`, a different axis from this ADR's within-game
splitting), ADR-010 (an earlier, narrower exception to ADR-001 for
TS-native-origin games).

## Context

ADR-001 locked every game to exactly three files — `data.yaml`,
`ui.yaml`, `logic.lua` — "no exceptions," to guarantee a portable,
reasonable-about-without-running artifact per game.

That rule is already not being followed. Shoal has five Lua files
(`utils.lua`, `state.lua`, `entities.lua`, `steering.lua`, `logic.lua`),
with no prior ADR authorizing the split — it happened organically as
the game grew, because a single file would have been unreasonable.
Confirmed directly: `logic.lua` is 18.4KB and mixes at least six
distinct responsibilities (lifecycle orchestration, spatial hash
maintenance, algae lifecycle, chunk lifecycle, discrete-event
simulation, render-state serialization). Brewfield's entire game is a
single 30KB `logic.lua`, the more extreme version of the same pattern.

The rule was right at the size that motivated it. It stopped being
right once a single game's logic genuinely outgrew what one file can
hold while staying reasoned-about. Leaving ADR-001's literal text
unenforced, silently, is worse than writing down what actually
happened and disciplining it.

## Decision

**`data.yaml`, `ui.yaml`, and `logic.lua` remain the three artifacts
that define a game** — ADR-001's actual goal (a portable, inspectable
contract per game) is unchanged. What changes: `logic.lua` may be
split into multiple files by genuine Separation of Concerns, once a
real size or responsibility threshold is crossed. `data.yaml` may
split the same way, under the same threshold, when it grows large
enough — not preemptively.

**The threshold, concrete, not a feeling:** a Lua file exceeding
**~8KB**, or mixing more than two genuinely distinct responsibilities
(not two functions that happen to both touch the same data), is a
real candidate for splitting. Below that, one file stays one file —
this ADR does not mandate splitting small games that don't need it.

**Single Responsibility, applied at file level:** each split-out file
owns exactly one concern, named for that concern, not for "part 2" or
"misc." A file that becomes a dumping ground for whatever didn't fit
elsewhere has failed the split, not succeeded at it.

**Discoverability is mandatory, not optional.** `systems.yaml`'s
`lua_files` list must enumerate every file, in load order, exactly as
it does today — ADR-001's "reason about the game without running code"
goal is preserved by keeping that list authoritative and complete, not
by keeping the file count low.

**Worked example — Shoal's real split, as the reference case:**

```
games/shoal/
  utils.lua              — generic math (unchanged, already correctly scoped)
  spatial_hash.lua        — rebuild_spatial_hash, get_nearby (split from logic.lua)
  algae_lifecycle.lua     — update_algae, starvation tracking (split from logic.lua)
  chunk_lifecycle.lua     — update_chunks, decompose_chunk (split from logic.lua)
  discrete_events.lua     — grazing/hunting/breeding (split from logic.lua)
  render_state.lua        — build_render_state, get_state_summary, count_* (split from logic.lua)
  forces.lua              — force_separate/align/cohere/arrive/avoid/wander (split from steering.lua)
  fish_steering.lua        — compute_fish_forces (split from steering.lua)
  shark_steering.lua       — compute_shark_forces (split from steering.lua)
  entities.lua            — spawning + per-entity update (audit for further split separately — not pre-judged here)
  state.lua               — GAME_STATE shape and init (unchanged, already correctly scoped)
  logic.lua               — init_game, tick_game only: orchestration, calling into the above
```

`logic.lua` becomes small and stays small — it's the table of contents,
not the book.

## Consequences

- Whoever implements a split must verify byte-for-byte that every
  function moved, none were duplicated, and every call site updated —
  same discipline as any other refactor in this project. This is not
  authorization to move fast; it's authorization to move at all.
- `forces.lua`'s contents (the Reynolds-named primitives) become a
  natural, low-risk candidate for eventual promotion to `engine/`
  under ADR-009 — *if* a second game ever needs continuous
  force-based steering. This ADR does not authorize that promotion
  now; it only notes the split makes that future decision cheaper
  when its real trigger arrives.
- `data.yaml`/`ui.yaml` splitting is authorized under the same
  threshold but not required anywhere today — no current game's
  config file has crossed it.
- This ADR does not touch ADR-001's three-*artifact-type* model.
  Every game is still `data.yaml` + `ui.yaml` + "the logic layer,"
  whether that layer is one file or nine.

*Robert Floyd Dugger's direct decision, July 2026 — unhinges ADR-001's
literal file count on purpose, keeps its actual goal intact.*
