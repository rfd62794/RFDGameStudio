# ADR-010: TypeScript-Native Origin Is Permitted — Lua Reserved for Genuine Cross-Language Portability

**Status:** Accepted
**Date:** July 25, 2026
**Supersedes:** ADR-001 ("no exceptions" clause), ADR-002 ("all future game logic lives here" clause) — for the specific case defined below only.
**Related:** ADR-005 (named patterns, not shared binaries), ADR-009 (shared Lua utility primitives)

## Context

ADR-001 defines every game by the three/four-file Lua contract with "no exceptions."
ADR-002 states Lua is the logic layer for "all future game logic." Both were written
before the studio began regularly importing standalone React/TypeScript prototypes
(from Google AI Studio, Bolt, and Replit) as the starting point for new games.

Porting Dissonance Depths from its verified TypeScript prototype into Lua surfaced
two real, repeated cost classes, not hypothetical risk:

1. **Translation loss.** Map generation, run-state transitions, and deck/hand
   management were never ported at all in the first pass — an entire subsystem
   silently didn't survive the language change, caught only because a later
   directive tried to build against it and found nothing there.
2. **Wiring loss.** `checkBuildGate` and four discovery-recording calls existed,
   correctly written, in both the original TypeScript and the first Lua port —
   and were never called from any real acquisition path in either. This exact
   disease was found and fixed twice independently during the same porting
   effort.

Both failure classes share one root cause: re-expressing working logic in a second
language creates a real chance of losing pieces of it, silently. This risk is the
actual price Lua's "one logic file runs in three host languages" guarantee is
paying for. That guarantee is valuable when a game genuinely needs to run its
logic across multiple host languages (VoidDrift's Rust core, TurboShells' Rust/
Python core, both real, both mid-port as of this ADR). It is a pure cost, with no
offsetting benefit, for a game whose logic will only ever run in one runtime —
which is the actual situation for any demo whose real origin is a standalone
TypeScript/React prototype.

ADR-005 already establishes that shared logic is a named pattern, not a shared
binary — meaning code reuse across TypeScript-native games was never going to
come from a shared Lua runtime in the first place. Nothing about keeping such a
game's logic in TypeScript forfeits any reuse the studio was actually getting.

## Decision

**A game whose real origin is a standalone TypeScript/React prototype (Google AI
Studio, Bolt, Replit, or hand-authored) defaults to remaining TypeScript-native.**
Its logic lives as pure, testable TypeScript functions — no I/O, no rendering,
matching the same purity discipline ADR-002 already requires of Lua — verified via
the studio's existing TypeScript test suite, not ported to `logic.lua`.

**Lua remains mandatory for two populations, unchanged:**

1. Every game already ported to Lua (Brewfield, SlimeWorld, Shoal, horse_racing,
   mutant_battle_ball, slither_rogue, scrapcrawl, and Dissonance's already-completed
   Lua work). Nothing here authorizes migrating any of these backward to TypeScript.
2. Any new game whose real origin requires genuine cross-language portability —
   concretely, a project originating in Rust or Python that is being brought into
   RFDGameStudio's own multi-runtime engine (VoidDrift, TurboShells). For these,
   ADR-001 and ADR-002 apply exactly as written, no exception.

**Before defaulting either way, a game's real origin must be checked, not assumed.**
A standalone React export sitting in `examples/` is not automatically TypeScript-
native under this ADR if its actual purpose is to seed a Rust- or Python-hosted
game (see VoidDrift's `web/` pilot, which is explicitly scaffolding toward a Lua/
YAML port, not a TypeScript-native destination itself).

## Rationale

Robert's direct decision, July 25, 2026, made during the Dissonance Depths port and
renderer work, after two independent instances of the translation-loss and wiring-
loss failure classes described above. The cost of the Lua hop for a TypeScript-
origin, single-runtime game was real and measured this session; the benefit was
never real for that case, since ADR-005 already means no shared Lua binary was
ever going to be gained.

## Consequences

- Dissonance Depths' render layer and any future AI-Studio/Bolt/Replit-originated
  demo may ship with TypeScript-native logic, verified by `npm --prefix ts run
  test`, without a corresponding `logic.lua`.
- The four-file contract (ADR-001, ADR-006) remains the mandatory, no-exception
  target for VoidDrift and TurboShells specifically, and for any future game
  whose real origin is a non-TypeScript host language.
- This does not authorize migrating any already-Lua-ported game backward. ADR-009's
  shared-Lua-utility precedent is unaffected for that population.
- A future shared-logic layer for TypeScript-native games, if one is ever
  justified, is a separate decision requiring its own ADR — this ADR does not
  pre-authorize it, matching ADR-005's own discipline of not building shared
  binaries ahead of proven need.
- Claude and any coding agent must state which path a new game falls under
  (TypeScript-native vs. cross-language-origin Lua) before scoping any port or
  build directive for it, and must not assume the answer from the source tool
  alone (AI Studio does not imply TypeScript-native destination — see VoidDrift).
