## MOMENT  
It’s 02:13 AM, the server room’s humming like a distant tide, and I’m perched on the folding chair by the rack, eyes glued to the terminal while the rain taps a Morse code on the window. The last build of **SlimeWorld** just finished, and the freshly‑generated `index.html` is staring back at me, a single line of code that decides whether the whole demo will load or explode in a 404.

## SURPRISE  
The `<script>` tag that should have pointed to `index-fX20-8aI.js` is still referencing the old hash `index-B4noau8-.js`. The build pipeline silently cached the previous manifest, so the browser is trying to fetch a file that no longer exists. The page loads, the console screams *“Failed to load module”*, and the entire arcade UI collapses into a blank screen.

## STRUGGLE  
- **Cache invalidation**: The Vite/ESBuild output directory (`ts/dist-slimeworld/assets`) was being cleaned only partially; the old hash persisted in the HTML template.  
- **Manifest sync**: The `index.html` generator reads a `manifest.json` that was never rewritten after the overnight `choke_point` and `wire_rust` prototypes were added.  
- **CI race condition**: Two parallel jobs (the prototype builds and the demo‑mode script ` _live_demo_json_mode.py`) both wrote to the same `dist` folder, causing the stale hash to win the merge.  
- **Debug path**: I had to force a clean (`rm -rf ts/dist-slimeworld/* && npm run build`) and then manually verify the hash in the generated HTML, which revealed the mismatch.

## LESSON  
*Never trust a build artifact that wasn’t produced from a pristine, single‑source‑of‑truth directory.*

## NEXT
