# ADR-003: Customer-as-Agent, Shared Bathroom, Compound Needs, Generic Worker Roster

*Status: Proposed. Larger than ADR-002; directly reopens two already-shipped pieces (Station Assignment framing, last directive's Brand Recovery), unlike ADR-002 which sat cleanly alongside existing work.*

## Context

Five real, connected pieces surfaced across this conversation, now resolved into one coherent shape: Customer gets the full Worker/Manager Layer 1/Layer 2 treatment (corrected from last message's undersized "reactive state machine" scoping — a customer choosing between their order, the bathroom, and an impulse second order is a genuine competing-candidate space, not a narrow one). Bathroom becomes a real, shared Station-adjacent capability — Queue + Occupancy Limit, contested by both Workers and Customers, the same real contention shape the Coffee Pot already proved out. A compound Needs system — Hunger and Thirst, cured differently, both feeding one shared Bladder accumulator. Free Meal becomes a real, Day-time, Stock-costed Brand Recovery action, distinct from and complementary to the Cash-costed Night version shipped two directives ago. And the Worker roster becomes generic and growable, specifically to unblock Hire/Fire — not a deeper architectural unification.

**Explicitly resolved, not open anymore:** no shared `Agent` base type across Worker/Manager/Customer. Each stays independently implemented; only real *patterns* (Needs, Bathroom contention) get reused across them, not a forced common interface.

**Explicitly distinct from ADR-002:** Bathroom's Queue+Occupancy contract has nothing to do with ADR-002's Raw/Processed/Combined Stock-flow model. This doesn't wait for "revisit at Coffee" — it's separate, smaller, real infrastructure that can proceed on its own schedule.

## Decision Points

### 1. Customer — full Layer 1/Layer 2 Agent

Real competing candidates:
```typescript
type CustomerTask = 'seek_original_order' | 'use_bathroom' | 'seek_additional_order' | 'leave';
```
- `seek_original_order` — pursue what they walked in for. Analogous to Protocol.
- `use_bathroom` — triggered by real, ticking Bladder need, same curve shape already proven for Worker Rest.
- `seek_additional_order` — real, new: once the original need is satisfied, a customer can genuinely opt into a second order. This is the one piece that breaks a real, current assumption — Customer currently maps to exactly one `orderId`. Needs deliberate handling: either `Customer.orderIds: string[]` or a real, explicit "current order" pointer that can be reassigned mid-visit.
- `leave` — terminal, once every real need resolves or Patience exhausts first.

Real Layer 2: genuine movement (Entrance → Order point → Bathroom if needed → Exit), replacing the current static spawn-and-sit sprite entirely.

### 2. Bathroom — shared Station-adjacent Queue + Occupancy capability

```typescript
interface OccupancyStation {
  occupancyLimit: number;      // real, upgradeable via Night Shop, same pattern as Buffer Capacity
  currentOccupants: string[];  // real IDs — Worker AND Customer IDs share one pool
  waitQueue: string[];
}
```
Genuinely shared contention between Workers and Customers, confirmed this message — same real shape as the Coffee Pot, applied to occupancy instead of depleting units.

### 3. Compound Needs — Hunger/Thirst, different cures, one shared consequence

```typescript
hunger: number;  // depletes over time; cured by eating (Worker: Meal; Customer: their food order)
thirst: number;  // depletes over time; cured by drinking (Worker: Coffee; Customer: Soda specifically)
bladder: number; // real, compound — increases from BOTH a real eating event AND a real drinking
                  // event, different causes, one shared accumulator, exactly as specified
```

### 4. Free Meal — real, Day-time, Stock-costed Brand Recovery

```typescript
export function offerFreeMeal(state: KitchenState, customerId: string): boolean {
  if (state.stockUnits < FREE_MEAL_STOCK_COST) return false; // real cost: Stock, not Cash
  state.stockUnits -= FREE_MEAL_STOCK_COST;
  state.brandEquity = Math.min(100, state.brandEquity + FREE_MEAL_BRAND_BONUS);
  state.totalFreeMealsGiven++; // new, real, tracked
  return true;
}
```
Distinct from the Night Cash-purchase Brand Recovery shipped two directives ago — this is faster, situational, costs a different real resource. Both stay; they're genuinely different tools, not duplicate implementations of the same idea.

### 5. Waste Cost / Free Meal tracking — real gap, closes automation's blind spot

```typescript
totalFreeMealsGiven: number;
totalWasteCost: number; // real, surfaced in the existing Nightly P&L report, not a new parallel display
```
The automation directive removed tedium and, as a side effect, made this economy's real numbers invisible along with it. This is the fix — feeding into infrastructure that already exists (the P&L report), not building a new one.

### 6. Generic Worker Roster — scoped exactly to what was asked, nothing more

`INITIAL_WORKERS` stops being the permanent cast; becomes the starting roster. A real hire function can add genuinely new, generically-templated Worker instances at runtime — same baseline stats, differentiated through real play via the already-existing `stationStats`. This directive does **not** build the full Hire/Fire economy (UI, cost, firing) — only the underlying capability: workers become a real, growable array instead of an architecturally-fixed cast of four.

### 7. Station Assignment — reframed, not removed

My position from last message, unchanged by this one: still real and valuable, reframed around assigning roles across whoever's currently on shift rather than getting to know named individuals. `stationStats` does the same real work either way — even a brand-new generic hire becomes individually differentiated through play.

## Real Costs, Stated Plainly

This is larger than ADR-003. Customer's Agent conversion alone is comparable to the original Manager-as-Agent build. It also directly touches two already-shipped things — Station Assignment's framing and last directive's Brand Recovery — rather than sitting cleanly alongside existing work the way ADR-002 does. Sequencing this seriously, not casually, matters more here than it did there.

## Real Open Question, Genuinely Unresolved

Where this sits relative to Fries/Coffee/Soda — ahead of the menu curriculum, or behind it — hasn't been decided. Nothing here makes the menu-tier work wasted if it ships first; they're orthogonal. That's a real, separate sequencing call, not a blocker to writing this down.
